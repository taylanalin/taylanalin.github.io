REST API tasarımı, API kapısını anlaşılır ve sürdürülebilir hale getirme yaklaşımıdır. Kaynak, metot, durum kodu, sürümleme ve hata cevabı gibi kavramlar burada önem kazanır. İyi tasarlanmış bir REST API, ne yapmak istediğini adından ve davranışından belli eder. Kötü tasarlanmış olan ise her çağrıda özel açıklama isteyen karmaşık bir geçide dönüşür.

Bir başvuru kaynağını düşün. Başvuruları listelemek, tek başvuruyu görmek, yeni başvuru oluşturmak, güncellemek veya iptal etmek farklı işlemlerdir. Bunların her biri tutarlı adresler ve HTTP metotlarıyla ifade edilirse geliştiriciler sistemi daha kolay anlar. Hata durumunda da yalnız “başarısız” demek yetmez; neden başarısız olduğu, kullanıcı hatası mı sistem hatası mı olduğu, tekrar denenip denenemeyeceği anlaşılmalıdır.

Yönetici açısından REST API tasarımı bakım ve entegrasyon maliyetini etkiler. Bugün bir sistemle konuşan API yarın mobil uygulama, raporlama aracı veya başka kurum entegrasyonu tarafından da kullanılabilir. Bu yüzden sürümleme, geriye uyumluluk, dokümantasyon ve güvenlik baştan düşünülmelidir. REST API tasarımını anlayan proje yöneticisi, “çalışıyor” cevabıyla yetinmez; “anlaşılır, güvenli ve yıllar sonra da yönetilebilir mi?” diye sorar.
